# Archie 1.0.0

Archie 1.0.0 is the first public release of the local-first architecture explorer and read-only MCP server.

## Highlights

- Scans a local repository without uploading source or requiring an account.
- Reconciles explicitly installed first-party scanner observations into deterministic architecture artifacts.
- Serves local dependency and inferred-runtime maps with evidence, provenance, diagnostics, search, and filters.
- Exposes four bounded, read-only MCP tools for context, dependencies, flow tracing, and potential change impact.
- Keeps scanner installation explicit and verifies catalog packages before activation.
- Preserves the last successful snapshot when scanning or validation fails.

The signed scanner catalog `2026-09-07.1` provides .NET scanner 1.3.0 and PHP scanner 2.0.0. Scanners are separate executable packages and are not bundled in the Archie archive.

## Supported package

The release contains one framework-dependent `linux-x64` archive. It requires:

- Linux x64
- .NET 10 SDK/reference packs
- Git
- util-linux `unshare` with delegated user and PID namespaces
- A browser for the visual explorer, unless `--no-browser` is used

Download both release assets and verify the archive before extraction:

```bash
sha256sum --check archie-linux-x64-1.0.0.tar.gz.sha256
tar -xzf archie-linux-x64-1.0.0.tar.gz
./archie-linux-x64-1.0.0/archie scanner recommend /path/to/repository
./archie-linux-x64-1.0.0/archie scanner add archie.dotnet
./archie-linux-x64-1.0.0/archie open /path/to/repository
```

Install every scanner recommended for the target repository. The checksum detects accidental or post-download changes, but this release is not independently signed; GitHub is the release trust root.

## Known limitations

- Linux x64 is the only packaged platform.
- The package is framework-dependent and requires the .NET 10 SDK/reference packs.
- Archie operates on one repository at a time; it does not compose repositories.
- Hosted repository connections, teams, persistent history, cloud execution, billing, and accounts are out of scope.
- Scanner process-lifetime containment is not a complete filesystem or network sandbox. Installing a scanner remains an executable-code trust decision.
- Missing dependency metadata can reduce semantic coverage. Archie reports diagnostics instead of restoring, building, or executing the analyzed repository.

See the [Linux release guide](https://github.com/Entorn-dev/archie/blob/v1.0.0/docs/local-linux-release.md), [scanner lifecycle guide](https://github.com/Entorn-dev/archie/blob/v1.0.0/docs/scanners.md), and [security policy](https://github.com/Entorn-dev/archie/blob/v1.0.0/SECURITY.md) for details.
